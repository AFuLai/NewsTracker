## 2. 為什麼目前感覺「好幾套混在一起」（Concrete Overlaps & Findings）

目前 [index.html](file:///opt/tracker/repo/ui/index.html) 是歷次功能迭代（MD3 改造 → 雙 Skin → 5 種 Layout Presets → Watch 規則 → Watch Hub 總覽 → 10 款 Palettes）逐層疊加的結果。舊系統未退場、新系統直接覆蓋在上面，導致**同一個概念在畫面上有 2～3 套控制項與程式碼路徑**：

### 2.1 三套色彩系統疊加：Skin (`md3`/`classic`) × Theme (`dark`/`light`) × Palette（10 款）

- **Finding F1（介面控制衝突與無效按鈕）：** Header 右上角同時擺放 `#skin-btn`（切換外觀）、`#palette-btn`（配色）、`#theme-btn`（切換深淺主題）三顆按鈕（ui/index.html:1424 `<button id="skin-btn" onclick="toggleSkin()" aria-label="切換外觀">` 至 ui/index.html:1428 `<button id="theme-btn" onclick="toggleTheme()" aria-label="切換主題">`）。當使用者選擇任一款 Palette 時，ui/index.html:836 `html[data-palette][data-skin][data-theme] {` 會強制覆寫 `--surface`、`--card-bg`、`--card-border-width: 1px` 等所有關鍵 Token；此時 `#theme-btn` 被鎖死 disabled（ui/index.html:2055 `tb.disabled = !!palettePref;`），而 `#skin-btn` 雖然還能點擊並改變 URL hash `s=classic`（ui/index.html:4176 `function toggleSkin() {`），但在畫面上**完全沒有任何視覺變化**，因為兩套 skin 的差異（`--surface`、`--card-bg`、`--card-border-width`、`--card-shadow`，定義於 ui/index.html:170 `[data-skin="md3"]     { --card-bg: var(--surface-container-low); --card-border-width: 0; }`）已被高權重的 palette 選擇器全數覆蓋。
  - 驗證指令：`sed -n '170,174p;836,856p;2053,2057p;4176,4181p' /opt/tracker/repo/ui/index.html`
- **Finding F2（元件內私自硬編碼第 4 套配色）：** 「我的關注」的儀表模式 `.wh-dash` 在 CSS 內私自宣告了一套 `--wh-bg: #070B12` 深海青變數（ui/index.html:1326 `  --wh-bg: #070B12; --wh-card: rgba(13,20,32,0.92); --wh-text: #DCE6F2; --wh-muted: #7F93AD;`），不走全域 `--surface` / `--on-surface` token。結果當使用者處於預設淺色主題（`data-theme="light"` 且無 `data-palette`）並切到「儀表」時，頁面下半部突然變成深色背景，與上半部淺色 Header 形成強烈割裂。

### 3.1 資料層（Data Layer：`TrackerStore`）— 純查詢 API，絕不碰 DOM

- **職責：** 管理 `window.TRACKER_MANIFESTS`、`window.TRACKER_YEAR`、`window.TRACKER_MONTH`、`window.TRACKER_DAYS` 與 `window.CRA_LIBRARY` 的非同步 `<script>` 注入、記憶體快取、跨日／跨庫 ID 去重、正規化與純函式查詢。
- **核心公開 API（全部無 DOM 依賴，可在 Node.js 直接測試）：**
  1. `await store.ensureLoaded({ windowDays, tracker, year, month })`：統一取代分散的 `ensureHubLoaded`、`ensureAllLoaded`、`selectYear`、`selectMonth` 載入鏈。
  2. `store.normalizeArticle(raw, date)`：在資料進入索引時一次性計算並快取正規化屬性：
     - `id`（穩定 ID `YYYYMMDD-dbid`，來自 tracker/render.py:116 `            "id": f"{day8}-{r['id']}" if r.get("id") is not None else f"{day8}-{i:03d}",`）
     - `date`（`YYYY-MM-DD`）
     - `typeId`（由 `newsTypeOf(raw)` 映射為 9 大新聞類型；若原始 `category` 為 `Linux/Windows/Apple/Android`，則依標題與標籤推導其新聞類型或歸入 `vuln`/`other`，同時將該平台名稱寫入 `platforms[]`）
     - `platforms[]`（從 `category` 與 `tags` 提取之平台清單）
     - `cves[]`（從標題與 `tags` 提取之 `CVE-YYYY-NNNN+` 陣列）
  3. `store.query(params, watchPrefs, lang)`：
     - **輸入 `params`：** `{ windowDays, year, month, date, sourceTracker, types, platforms, tags, search, searchScope, watchOnly }`
     - **輸出：**
       - `articles`：去重且依日期與優先序排好序的文章陣列（每篇附帶 `matchedRules` 與 `isRead`）。
       - `aggregates`：`{ total, byType, byPlatform, byTag, watchHitsByRule, series14ByType, dateCounts }`。
  4. `store.getReaderContext(articleId, currentQueryArticles)`：
     - 回傳 `{ article, index, total, prevArticle, nextArticle, nextInType, sameCveArticles, relatedByTagArticles }`，直接供給沉浸式閱讀器渲染上下篇、同 CVE 事件脈絡與同類型下一篇！

### 3.2 狀態層（State Layer：`TrackerState`）— 單一儲存鍵 + URL Hash 編解碼器

- **職責：** 集中管理「使用者長期偏好（`prefs`，持久化至單一 `localStorage` key `tracker_prefs`）」與「當前導覽路由（`route`，雙向同步至 `location.hash`）」。
- **單一儲存鍵與自動遷移：**
  - `loadPrefs(storage)`：若 `tracker_prefs` 存在且 `v === 2` 直接解析；否則呼叫 `migrateV1ToV2(storage)` 讀取 §1.2 所列的 10 個舊 key，轉換為 `v: 2` 結構。
  - `savePrefs(prefs, storage)`：檢查 `isPreviewMode()`（`?pv=1` 時不寫入），以 `try { storage.setItem('tracker_prefs', JSON.stringify(prefs)); } catch(e) {}` 寫入。
- **URL Hash 雙向 Codec（100% 向後相容現有 Permalinks）：**
  - `parseHashRoute(hashStr)`：
    - 支援舊連結：`#t=security&y=2026&m=2026-10&d=2026-10-19&c=...&q=...`、`#hub=1&hv=tiles&hw=30`、`#lib=1&c=...&g=date`、`#pal=deepsea&p=quick`。
    - 支援新閱讀器連結：`#a=20261019-42`（可單獨使用，或疊加在任何列表狀態後，如 `#hub=1&hw=30&type=vuln&a=20261019-42`）。
  - `serializeHashRoute(route, prefs)`：產生精簡且可分享的 hash，當閱讀器開啟時自動帶上 `&a=<articleId>`，關閉時移除 `a=`。

### 3.3 顯示層（View Layer：`TrackerView`）— 純渲染元件 + 單一 Token 系統

### 4.5 沉浸式閱讀 8 大細節規格

1. **雙欄／全螢幕模式切換（Reader Mode）：**
   - 桌面端（`≥ 1100px`）預設為 Master–Detail 雙欄並排，使用者可一邊掃描左側標題流、一邊在右側連續讀內文，無須反覆開關彈窗；亦可按 `f` 鍵或 `⤢` 切換居中單欄專注模式（Zen mode）。
   - 手機端（`< 600px`）為全螢幕視圖，支援原生瀏覽器返回鍵（透過 URL hash `a=<id>` 與 `hashchange` 連動）。
2. **排版與字體控制（Typography & Measure）：**
   - **最佳行寬（Measure）：** 正文容器設定 `max-width: 65ch`（英文約 65–72 字元、繁體中文約 32–36 個全形字），避免寬螢幕視線長距離跳行疲勞。
   - **CJK 友善行高與段落：** 中文模式預設字級 `18px`、`line-height: 1.85`、段落間距 `margin-bottom: 1.15em`、`letter-spacing: 0.015em`；英文模式預設 `18px`、`line-height: 1.68`。
   - **段落化呈現：** 將摘要中的句號或換行（以及未來 refs/plans/20261019-watch-and-frame-decisions.md:15 `涉及對象 / Who · 影響地區 / Where · 起因 / Why · 經過／手法 / How · 影響範圍 / Impact ·` 的結構化 `frame` 欄位）渲染為清晰的重點摘要卡 + 分段內文，不再擠成一整塊文字牆。
   - **字級控制（`Aa`）：** 提供 4 階字級（標準 `16px` / 舒適 `18px` / 大字 `20px` / 特大 `22px`），儲存在 `tracker_prefs.reader.fontSize`。
     - *設計系統守門相容性注意：* ui/audit.js:162 `    out.push(chk('B1 distinct font sizes <= 5', fontSizes.size <= 5,` 要求預設狀態下全頁不同 `font-size` 數 `<= 5`。因此預設字級對齊現有尺度（`12px` / `13px` / `14px` / `18px` / `22px`），僅在使用者主動調整 `--reader-font-size` 時覆寫閱讀器正文。
3. **鍵盤快捷鍵（Keyboard Navigation）：**
   - 當焦點不在 `<input>` / `<select>` / `<textarea>` 時：
     - `j` 或 `ArrowRight`：直接切換至當前清單的**下一篇**文章（若閱讀器未開則開啟第一篇）。
     - `k` 或 `ArrowLeft`：直接切換至當前清單的**上一篇**文章。
     - `Esc`：關閉閱讀器並將焦點還原至觸發卡片（維持 ui/audit.js:306 `    out.push(chk('D7 focus restored to source card', d7, {}));` 通過）。
     - `m`：切換當前文章「已讀／未讀」狀態。
     - `v` 或 `o`：於新分頁開啟第一則原始新聞來源（驗證 `safeHref`，ui/index.html:4159 `function safeHref(u) {`）。
     - `f`：桌面端切換「雙欄並排 ⇄ 專注全寬」。
4. **手機滑動手勢（Swipe on Phone）：**
   - 在 `#reader-pane` 綁定被動觸控偵測（`passive: true`），當 `Math.abs(dx) > 60 && Math.abs(dx) > 2 * Math.abs(dy)` 時：左滑呼叫 `openNextArticle()`、右滑呼叫 `openPrevArticle()`。
5. **閱讀進度與已讀狀態（Progress & Read State）：**
   - **單篇捲動進度條：** 閱讀面板頂部設 2px 進度條（`scrollTop / (scrollHeight - clientHeight)`），長文或含多關聯文章時一目了然。
   - **清單位置指示：** 頂欄顯示 `第 3 / 24 篇`，掌握目前在篩選清單中的進度。
   - **本地已讀紀錄（Read Markers）：** 點開文章滿 1.5 秒（或捲動到底）自動將 `article.id` 記入 `prefs.readState.readIds`（上限 3000 筆 FIFO，且 `?pv=1` 不寫入）。清單中未讀文章顯示醒目標題與左側圓點 `●`，已讀文章標題降為 `var(--on-surface-variant)` 並標示 `✓`，使用者亦可隨時按 `m` 標回未讀。
6. **閱讀時極簡外框（Minimal Chrome While Reading）：**
   - 閱讀面板內部移除所有分類色塊噪音，只留頂部微幅工具列；在手機端或桌面 Zen 模式下，捲動閱讀正文時頂部導覽不佔位。
7. **文末來源與相關文章聚類（Sources & Related Articles — Same CVE / Cluster）：**
   - 文末第一區：**原始報導來源**（顯示語言標籤 `[EN]`/`[ZH]`、媒體名稱、網域，點擊開新分頁）。
   - 文末第二區：**同事件／相關追蹤（純前端即時聚合，不需等後端 pipeline）**：
     - 優先比對**相同 CVE 編號**（例如同含 `CVE-2026-12345` 的跨日文章，按日期倒序排列，呈現事件時間軸）。
     - 若無 CVE，比對目前已載入視窗中**共享 `>= 2` 個相同標籤（`articleTags`）**的文章（最多取 5 篇），點擊直接在閱讀器內無縫切換！
8. **「同類型下一篇」（Next in This Type）：**
   - 文末底部設有一張大尺寸預覽卡「下一篇〔漏洞威脅〕：`<標題>` ▸」，即使使用者從「我的關注」分區首頁（每區預設只露 6 篇）點進來，也能在閱讀器內一路順著同一個新聞類型讀完全部文章，不必退回首頁點「全部 ›」。

## 5. 統一導覽模型與資訊架構樹（One Navigation Model）

### 5.1 如何無損整合「我的關注總覽」、「依來源歷史歸檔」與「CRA 參考圖書庫」

目前網站之所以分裂，是因為把「我的關注（近 7/30/90 天跨庫）」與「依來源瀏覽（單一 tracker 歷史年月）」做成兩個互斥的頁面模式（`selectHub` vs. `selectTracker`），各自擁有不同的篩選器與版型控制。

**統一方案：**
- 全站只有**兩個頂層工作區分頁**：
  1. **📰 新聞追蹤（News Workspace — 預設）**：將「我的關注總覽」與「歷史歸檔」**合而為一**！
     - **時間範圍選擇器（Window / Archive Picker）**：預設為「近 30 天」（可選 `近 7 天`、`近 30 天`、`近 90 天`、`📅 歷史年月歸檔 YYYY / MM / DD`）。當選「歷史年月歸檔」時，展開年月／日期選擇器（即原本的 Archive 能力）。
     - **來源篩選（Source Filter）**：預設為「全部來源（資安 + EU CRA + 作業系統）」，也可單選「僅資安」、「僅 EU CRA」、「僅作業系統」（即原本 `#src-menu` 的能力，但現在同樣享有新聞類型分區、平台標籤、儀表磚與沉浸式閱讀器！）。
  2. **📚 CRA 法規文件庫（CRA Reference Library）**：保留 `data/cra_library.js` 的 94 個官方主題目錄（依分類／日期／來源排列），共用同一個頂部 Header、搜尋框（可在 CRA 庫內即時過濾標題／來源！）與主題配色。

## 7. 風險與需請使用者裁決的 4 個簡單決定（Risks & Decisions）

### 7.1 主要技術風險與緩解措施

1. **[audit.js](file:///opt/tracker/repo/ui/audit.js) 既有自動化守門契約相容性風險：**
   - ui/audit.js:405 `      localStorage.setItem('tracker_theme', before === 'dark' ? 'light' : 'dark');`、ui/audit.js:476 `      localStorage.setItem('tracker_skin', before === 'md3' ? 'classic' : 'md3');` 與 ui/audit.js:495 `    if (typeof toggleSkin === 'function') {` 直接讀寫舊 key 與呼叫 `toggleSkin()`；且 ui/audit.js:162 `    out.push(chk('B1 distinct font sizes <= 5', fontSizes.size <= 5,` 限制預設畫面字級種類 `<= 5`。
   - **緩解：** 在 State 層保留對 `tracker_theme` / `tracker_skin` 的同步讀寫 shim 與 `toggleSkin()` 函式，並確保閱讀器預設字級復用既有 `18px` / `22px` 階梯（僅在使用者自訂字級時改變 `--reader-font-size`），或是由 session 授權於切片 M3 同步更新 [audit.js](file:///opt/tracker/repo/ui/audit.js)。
2. **歷史歸檔全量載入記憶體風險：**
   - 若使用者在統一視圖選擇「全年」且「全部來源」，載入整年所有 `data-YYYYMMDD.js` 檔案數較多。
   - **緩解：** 預設維持「近 30 天」視窗；當切換至「歷史年月歸檔」時預設載入單月（與現有 `selectMonth` 行為一致），僅在明確點選「全年」時批次載入。
