I implemented S6 and S7 in `ui/index.html`, the only file I changed. I checked that the script blocks pass `node --check`. I did not run the page in a browser, so the filter and timeline behaviour is untested.

**S6 (preset default filters)**
- `quick` now has `filters: { tracker: 'security', categories: ['重大事件', '漏洞與威脅情報'] }`, and `resolvePreset` returns it.
- A new `applyPresetFilters()` does the work. It applies only when the current tracker is the preset's tracker. It skips any category name that isn't in that tracker's manifest categories, then calls `refreshCatPills`.
- `selectTracker` calls it after it resets `state.filterCats`, unless a hash restore is running. So a `c=` value in the URL wins, and a link with no `c=` still means "all". The `c=` handling in `applyHashRestore` now clears `filterCats` before adding, so it can't merge with preset filters.
- `setPreset` also calls it before re-rendering, so choosing a preset from `view-select` applies its filters. Pill clicks afterwards stay untouched until the preset is chosen again.

**S7 (event timeline)**
- `LAYOUT_FALLBACK` is now empty, and `renderArticles` sends the `timeline` layout to a new `renderTimeline`.
- It uses the same CVE regex as the card tags, on `artTags(a)`. An article with several CVEs appears under each one.
- Each group has a header with the CVE id, the article count and the date span, then its rows (via `buildRiverRow`) newest first. Groups are sorted by latest date, newest first.
- Articles with no CVE go under "其他" / "Other" in a river-style list, with the heading from new `I18N.ui` keys `tlOther` and `tlCount`.
- `#article-count` is set before the layout dispatch, so it shows the same number as the other layouts.
- The `river` CSS rules are now shared with `timeline`.
