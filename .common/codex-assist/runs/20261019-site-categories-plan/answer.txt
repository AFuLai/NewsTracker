## 2. 選項

### 選項 A：第二排 pill 取代折疊（只改呈現）
- **畫面**
  - security 頁：維持 5 個安全 pill，下方新增一排「平台」pill：Linux、Windows、Apple、Android。卡片 badge 改顯示平台色，不再顯示 🔴 漏洞。
  - os 頁：保留 5 個 pill，新增一排「類型」，只放值得獨立的外來分類，目前只有「漏洞與威脅情報」443 件。
  - 小量外來分類（security 頁的開源影響 29、研討活動 21、法令更新 18、合規指引 12、調和標準 5、亞太對應 1，合計 86，ESTIMATE）維持折疊，不單獨成 pill。
  - 第二排與第一排共用同一個多選 `filterCats`（OR 語意），所以 hash 的 `c=` 不用改格式，`c=Linux` 可直接還原。
- **要改的程式**
  - `CAT_MAP.security`（1316–1317）移除 4 個平台項。
  - `CAT_MAP.os`（1333）移除「漏洞與威脅情報」一項。
  - `buildCatPills` / `refreshCatPills`（1811–1842）支援分組列。
  - 新增一個 UI 常數，指定各 tracker 的第二排內容。因為 manifest 的 `categories` 只有原生分類。
  - 加一點 CSS 讓第二排換行。
  - `renderArticles`（1942）與 `buildSearchIndex`（1225）不用改，它們已經走 `effectiveCat`。
- **風險**
  - 舊的 security 永久連結 `c=漏洞與威脅情報` 會變窄，從約 67% 降為只含原生漏洞文章。
  - `refreshCatPills` 目前用 `data-cat` 當 key 與 CSS 選擇器，要確認第二排不會因同名 pill 重複而互相影響（我沒有實測）。
  - 搜尋與月份選單沿用同一邏輯，行為一致。
  - 手機寬度下兩排 pill 會多占垂直空間。
- **分類**：不需要改 searchinfo 或 LLM prompt。
- **預估效果**（ESTIMATE）
  - security 漏洞 pill 降到 2675/6536，約 41%。
  - 前瞻技術不再混入 重點關注（325）。
  - 平台合計 1707（997+411+180+119）會有自己的入口。

### 選項 B：pill 計數＋移除最差的折疊（只改呈現，最輕）
- **畫面**
  - 每個 pill 顯示件數，例如「漏洞與威脅情報 (123)」。
  - 0 件的 pill 變灰。
  - 修掉語意最差的兩條折疊：`'重點關注':'前瞻技術'`、`'研討活動':'前瞻技術'`。
- **要改的程式**：`refreshCatPills`（1840 `btn.textContent = check + (btn.dataset.icon || '') + catLabel(c);`）、`CAT_MAP`，另外要有計數來源。
- **計數範圍**：只算目前載入的日期很容易誤導；要全時段就得讓 manifest 帶計數（動到 `tracker/render.py:241 `"categories": meta.get("categories") or [],`` 的輸出，屬資料管線）。
- **風險**：永久連結與搜尋不受影響。計數若隨搜尋與月份變動，要先說清楚是哪個範圍。
- **缺點**：67% 的集中度不變。
- **分類**：不需要改；若要全時段計數則需改建置輸出。

### 選項 C：主題標籤列＋「今日重點」hero
- **畫面**
  - eu_cra 頁上方加標籤 chip（CRA、SBOM、KISA…），點擊用標籤篩選。
  - 每頁最上方加「今日重點」區塊，放最新一天的前 N 件。
- **要改的程式**
  - 新增 `state.filterTags`。
  - hash 新增參數；但 `c=` 在 library 模式已被 cluster 佔用（2217、2260），要另取名。
  - `renderArticles`、`buildSearchIndex` 各加一段過濾。
  - 新增 hero 的 DOM 與 CSS。
- **風險**
  - 標籤沒有正規化。CRA 與 Cyber Resilience Act 分開計（26 與 17），AI 與 AI安全 也是（40 與 29），chip 會重複。
  - 沒有排序訊號可選 hero，見上方 grep。
  - 標籤列只是把 產業動態 的漂移藏起來，沒有修正。
- **分類**：需要。標籤別名表、重要度欄位或 LLM 輸出的排序訊號，都超出純呈現。

## 3. 建議

**採用選項 A，第二步再加選項 B 的計數；選項 C 暫緩。** 理由：
- A 直接解決最大的兩個問題：security 的 67% 與 os 的 40%。
- A 只動呈現，現有 CSS 都已備好，且與 hash、搜尋、月份選單相容。
- B 若要全時段計數，會牽涉資料管線，應該獨立評估。
- C 需要的標籤正規化與排序訊號目前都不存在。

eu_cra 的產業動態（46%）建議另開一個分類審查，不要靠 UI 遮蓋。我不裁定這是否為誤分類。

**需要你決定：**
1. 第二排用 OR（與第一排同一個多選）還是 AND？我建議 OR，格式不變。
2. 舊永久連結 `c=漏洞與威脅情報` 在 security 頁範圍變窄，是否接受？
3. 第二排清單寫在 UI 常數，還是放進 manifest？
4. 要不要做全時段計數？這會碰管線。
5. 是否另外開 eu_cra 產業動態的分類審查？

```
CODEX-ASSIST-GAP
  kind: acceptance
  question: 「今日重點」要以什麼準則挑選文章（重要度、來源、分類）？
  blocked-by: 程式碼與 ui 內沒有任何 importance/priority/featured 欄位（grep 命中 0）
  needed: 使用者定義挑選準則，或指定要由 LLM 產出的排序欄位
```
```
CODEX-ASSIST-GAP
  kind: scope
  question: security 頁 stored category 為 uncategorized 的 31 件，實際存的值是什麼？該歸哪個 pill？
  blocked-by: 我沒有讀 DB，也沒有被指定可讀的資料檔
  needed: 該欄位的實際值，以及歸屬規則
```
