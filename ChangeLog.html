Tracker ChangeLog

本檔由 tracker pack 自動維護；每次打包前由本地 ollama 生成版本重點並 prepend 於下方。

v0.6 — 2026-05-29

  • ✨ 新增功能 (CLI)：新增 `fetch --query-prefix` 參數。使用者可以為所有 DDG 網站搜尋查詢添加任意前綴字串，大幅提升在一般媒體網站上搜尋特定主題（例如歐盟法規）的相關性。

    ⚠️ 備註：此功能特別提升了資安新聞抓取覆蓋率和主題聚焦度。

  • 🐛 Bug 修復 (UI)：修復了多追蹤器（multi-tracker）的年份檢視錯誤。現在能正確讀取所有追蹤器的月份資料，避免顯示空年視圖。
  • 🚀 效能/功能提升 (CLI)：強化網站關鍵字搜尋邏輯，透過 `query_prefix` 參數，讓使用者能更精準地鎖定特定主題，提升資訊的聚焦度。
  • 💡 使用建議：針對難以抓取的官方網站（如 ENISA, EUR-Lex），目前最佳的本地化搜尋路徑是結合 `--query-prefix` 參數進行 DDG 搜尋。

v0.5 — 2026-05-29

  • 🚀 新增多追蹤器支援 (Multi-tracker Support)： 支援同時追蹤多個主題，目前已整合「資安」與「歐盟《爬蟲法案》 (EU CRA)」兩個頂層追蹤器。這使得資料結構更為精細，每個項目可透過 `trackers[]` 欄位標記其所屬的追蹤主題。
  • 🔍 提升資料準確性與關聯性： 優化了跨追蹤器（cross-belonging）的判斷邏輯，現在要求更嚴格的條件（如：窄域白名單、強標記和至少 3 個獨特 Token 重疊），避免了廣泛媒體域的誤判。
  • 🛠️ 關鍵修復與 CLI 升級： 修正了在切換追蹤器時，寫入（write）操作可能導致大量資料遺失的嚴重 Bug。同時新增了 `--tracker` 旗標，並加入 `cross-scan` 子命令，用於重新評估現有日期的多追蹤器歸屬。
  • 💾 增強資料遷移能力： 引入了 `migrate-v2` 子命令，可安全地將舊版資料（manifest-*.js）遷移到新的資料結構中，並自動為所有舊資料注入 `["security"]` 追蹤標籤。
  • 🌐 支援多來源追蹤： 透過新增的 `searchinfo_eu_cra.md` 來源，成功整合了第二個頂層追蹤器（EU CRA），大幅擴展了追蹤的覆蓋範圍。
  • ✨ 介面與使用者體驗優化： 網頁介面（index.html）新增了追蹤器標籤（Pills），並在文章篩選時，可根據項目所屬的追蹤器進行精準過濾。

v0.4 — 2026-05-29

  • 【介面/展示】優化每日報表排序邏輯：內容將依據預設的「分類優先級」（重大事件 → 法規 → 漏洞 → 供應鏈 → 前瞻）進行排序，讓用戶能更快速掌握重要資訊。
  • 【資料處理】強化分類（Category）處理機制：新增了 LLM 輸出驗證與分類強制轉換（Coercion）邏輯，確保即使資料庫存在過時或不準確的分類記錄，系統也能自動修正並正確歸類。
  • 【核心功能】提升內容聚類（Clustering）的召回率與準確性：降低了聚類閾值，並新增了「同來源資料防合併」機制，除非有明確的 CVE 橋接，否則不會將來自同一來源的資料誤判為同一事件。
  • 【穩定性/修補】增強資料寫入的健壯性：在摘要文章寫入資料庫前，會先對 LLM 輸出的分類結果進行嚴格驗證，防止因模型輸出錯誤導致資料庫污染。
  • 【效能/API】整體後端邏輯優化：修補了多個層級的分類處理流程，提升了資料處理的穩定性與資料一致性。

v0.3 — 2026-05-29

  • 【新功能/CLI】 增強摘要功能，新增 `--since` 和 `--until` 參數，允許使用者在 CLI 執行時對新聞來源日期進行精準的預過濾與後過濾。
  • 【來源優化/覆蓋率】 提升新聞抓取穩定性與覆蓋率：優化 `sources/site.py` 邏輯，新增更嚴格的 URL 篩選機制，有效排除 `/category/`、`/tag/` 或 `/page/N/` 等非文章頁面，確保抓取內容的準確性。
  • 【新功能/Prompting】 引入「類別感知提示」（Category-aware Prompting）機制。系統現在能從配置中讀取各類別的描述，並將這些定義資訊傳遞給 LLM，使摘要內容更具上下文相關性。
  • 【效能/穩定性】 修正了 `sources/stealth.py` 中的執行緒鎖定問題，確保在多執行緒環境下執行 `curl_cffi` 時的穩定性，提升爬取流程的可靠性。
  • 【模型部署】 更新了 README 文件，新增了關於 `OLLAMA_NUM_PARALLEL` 的部署指南，方便使用者在不同環境下優化 Ollama 模型的運行資源。
  • 【修補/優化】 改善了重複資料檢測（deduplication）邏輯，現在可以持久化儲存已跳過的窗口狀態（`skipped_window`），避免在重新執行時重複處理已處理的資料。

v0.2 — 2026-05-29

  • 【新功能/來源】擴充內建來源支援，新增多個主題的 RSS/FEED 來源（如 DR、iThome、資安人、Elastic、Ubuntu），並優化來源解析，提升資料擷取範圍。
  • 【內容擷取/效能】優化文章內容抓取流程，新增全文本（Full-text）擷取模式，並結合 `trafilatura` 提取文章日期，確保資料的完整性與時效性。
  • 【資料處理/API】升級資料整合能力，引入基於 Jaccard 或共享 CVE 的標題聚類（Clustering）機制，能夠自動跨來源合併重複或相關的文章，提升資料的覆蓋率。
  • 【CLI/效能】優化 CLI 流程：`summarize` 指令現在採用「分階段處理」機制，第一階段採用多執行緒並行抓取內容，第二階段則串行呼叫 Ollama 模型進行摘要生成。
  • 【CLI/功能】新增強大的搜尋與寫入功能：CLI 支援透過 DuckDuckGo 進行站點限定搜尋（`--site-search`），同時 `write` 指令增加寫入保護機制，防止無意間覆蓋資料。
  • 【資料完整性】提升資料寫入的健壯性，新增寫入防護機制，若未明確使用 `--force` 參數，系統將拒絕覆蓋現有資料，確保資料庫的穩定性。

v0.1 — 2026-05-29

  • 核心架構建立與 CLI 介面： 首次發布了完整的專案骨架，包含命令行介面 (CLI)、配置管理、資料提取、內容去重等核心模組，讓使用者能透過統一的介面操作所有功能。
  • 多樣化資料來源支援： 支援多種資料擷取來源，包括 API 介面、RSS Feed、本地檔案路徑 (Path) 以及更進階的 Stealth 來源，大幅提升資訊抓取能力。
  • 內容處理與 LLM 整合： 引入了資料去重 (deduplication) 邏輯，並整合了 LLM 處理模組，用於內容摘要、分析與結構化處理。
  • 打包流程建立： 完善了內容的打包與渲染機制，能夠將抓取到的多源資料轉換為標準化的輸出格式。 [✨ 標註：打包流程相關]
  • 錯誤處理與穩定性修復： 修復了自測試的退出處理邏輯，並強化了內容分類 (CATEGORY) 分隔符號的過濾條件，提升系統穩定性。
