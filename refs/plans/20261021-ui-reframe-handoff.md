# UI 改版接手單（2026-10-21）：資料與顯示脫鉤、高密度卡片、彈出閱讀

清除對話後從這裡開工。本檔記錄使用者的裁示（附原話）、設計正本與切片順序。

## 使用者裁示（2026-10-21）
- 「既有設計應該是框架化，要能將資料與顯示脫鉤，針對顯示進行改造，目前的設計感覺好幾套混在一起……幾個大功能要保留，只是改呈現方式，最主要是讀取新聞的沉浸感。」
- 「新聞數量多、分類多時，同一個畫面的檢索資訊密度低。另外，目前的新聞內容都是摘要，並非完整新聞內容，應比較適合卡片或者彈開畫面。」
  → 架構規劃決策 1 **不採用**左右雙欄閱讀，改為**高密度卡片＋彈出閱讀**。
- 「時間範圍選取沒有完整」→ 時間面板要有：快選（今天／7／30／90 天／今年／全部）、自訂起訖日、歷史年份歸檔、每日篇數長條圖（點一天只看當天）。
- 「側邊欄跟時間面板應該要能收折」，並且「應該可以整合成一列」→ 時間範圍是標題列上的一顆 chip，點了展開或收合時間面板；側邊欄收合後剩窄欄，只顯示類型色塊。
- 架構規劃的決策 2–4 照建議採 A：
  - 2：移除「檢視模式」下拉與「切換外觀」鈕，改用單一主題系統。
  - 3：依來源瀏覽併入同一個新聞工作區，「來源」和「年月」改為篩選條件。
  - 4：先做純前端的閱讀升級，不等 pipeline 產出 frame 欄位。

## 切片順序（每片都要能單獨上線，舊永久連結繼續可用）
1. **M1 資料層：** TrackerStore，提供純查詢與去重；加上 `getReaderContext`，取得同 CVE 文章與下一篇。
2. **M2 狀態層：** 10 個 localStorage 鍵合併成 `tracker_prefs` 並遷移；hash codec 支援 `a=<id>`。
3. **M3 單一主題 token：** 合併外觀、亮暗、配色三套；移除失效的控制項；儀表模式改用主題 token。
4. **M4 單一工作區：**
   - 左側類型欄（附篇數，可收合）。
   - 時間 chip 加可收合的時間面板。
   - 來源改為篩選條件。
   - CRA 庫成為第二個頂層分頁。
5. **M5 高密度卡片：** 一列 4 張卡片（卡片／標題兩種顯示），依日期分組。
6. **M6 彈出閱讀：**
   - 完整摘要、標籤、原文連結、同事件時間軸。
   - ←→ 切換上下篇，Esc 關閉。
   - 記錄已讀。
